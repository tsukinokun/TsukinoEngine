# TsukinoEngine コメント規約

コメントは**日本語**で記述する。稀に別言語が混入するため厳密に日本語で書くこと。
初学者にも分かるよう、各処理に丁寧にコメントを付ける。

## 基本

- `//` で書き、直後にスペースを1つ空ける（`// コメント文`）
- Doxygen 対応は `//!` または `//!<`
- 変数宣言の説明は右側に書く

```cpp
int value;    // コメント文
```

## 文体

| 対象 | 文体 | 句点 |
|---|---|---|
| 関数の要約（`@brief` 相当） | **です・ます調**の文章 | 付ける |
| それ以外（処理内容の説明など） | **体言止め**（「〜の処理」「〜を設定」） | 付けない |

関数の要約では「この関数は〜」という主語は**必ず省略**し、
「（目的語）を〜します。」のように目的語または動詞から始める。

```cpp
//【良い例】主語を省略し、動詞から始めている
//  バッファを作成します。

//【悪い例】「この関数は」という冗長な主語が含まれている
//  この関数はバッファを作成します。
```

## `@brief` の厳格なルール

- `@brief` は**ファイル先頭のファイルコメントブロック内でのみ、ただ一度だけ**使用が許可される
- それ以外のすべての場所（関数、クラス、構造体の要約）で `@brief` を使用することは**固く禁止**する
- 要約は常に `//!` の直後に書く

```cpp
//! これは要約です。          <- 正しい
//! @brief これは要約です。   <- 禁止
```

## ファイルコメント

ファイルの**最も先頭**に置く。76文字のハイフン `-` の罫線で囲む。

```cpp
//----------------------------------------------------------------------------
//! @file   VulkanDevice.cpp
//! @brief  Vulkan RHI の実装
//! @detail Vulkan の論理デバイス生成とコマンド送信を担当します。
//----------------------------------------------------------------------------
```

1. `@file` — ファイル名
2. `@brief` — ファイルの概要を**体言止め**で簡潔に
3. `@detail` — 役割や処理内容の詳細を**です・ます調**で

`@brief` と `@detail` がほぼ同じ内容になる場合は `@detail` を省略してよい。

## 関数コメント

**各関数のコメントブロックの直前には、必ず1行の空行を挿入する。**

### ヘッダファイル（.h / .hpp）

要約・引数・戻り値の**すべて**を書く。

```cpp

//! バッファを作成します。
//! @param  [in] desc バッファデスクリプタ。
//! @return 作成されたバッファリソース。
std::unique_ptr<Resource> CreateBuffer(const BufferDesc& desc);
```

- `@param [in/out] name 説明` の形式。入力のみ `[in]`、出力のみ `[out]`、入出力両方 `[in,out]`
- 戻り値が無ければ `@return` は不要
- `@` の後の記述は、**空白区切りの位置を前後のコメントと揃える**

```cpp
//! @param  [in] value         変数名コメント
//! @param  [in] longValueName 長いコメント
//! @return 戻り値
```

### ソースファイル（.cpp）— ヘッダに宣言が【ある】場合

**まず、その関数の宣言がヘッダに存在するかを必ず確認する。**
`public` / `protected` / `private` を問わず、ヘッダで宣言されているすべてのメンバ関数が対象。

罫線で囲んだ**要約コメントのみ**を書く。
`@param` や `@return` はヘッダ側に集約されているため、**.cpp には絶対に書かない**。

```cpp
//----------------------------------------------------------------------------
//! バッファを作成します。
//----------------------------------------------------------------------------
std::unique_ptr<iRHI::Resource> VulkanDevice::CreateBuffer(const iRHI::BufferDesc& desc)
{
    // ...実装...
}
```

### ソースファイル（.cpp）— ヘッダに宣言が【ない】場合

`static` 関数やラムダなど、.cpp が唯一のドキュメント場所になるもの。
**すべての解説（要約・`@param`・`@return`）を .cpp 側に書く**（ヘッダの場合の規則に準じる）。

```cpp
//----------------------------------------------------------------------------
//! Vulkan バリデーションレイヤーのデバッグコールバック関数です。
//! @param  [in] messageSeverity メッセージの重要度
//! @param  [in] messageType     メッセージの種類
//! @param  [in] pCallbackData   コールバックデータ
//! @param  [in] pUserData       ユーザーデータ
//! @return 常に VK_FALSE を返し、実行を継続します。
//----------------------------------------------------------------------------
static VKAPI_ATTR VkBool32 VKAPI_CALL DebugCallback(...)
{
    // ...実装...
}
```

## エラーメッセージ

ログメッセージは**英語**で、原因と影響が分かるように書く（コメントは日本語、ログは英語）。

```cpp
MessageBoxA(nullptr, "Failed to load shader.", "Error", MB_OK);
```

## 罫線について

このリポジトリの既存コードには、ファイルコメントに 61文字の `-` を使っている箇所も混在している。
**新規記述と修正時は 76文字**に揃える。既存ファイルを編集する際は、そのファイル内の
既存の罫線幅に合わせてもよい（一貫性を優先する）。
